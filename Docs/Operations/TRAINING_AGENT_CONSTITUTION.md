## 一、权限、命名与交付

- Owner 决定训练成果何时提交、何时交给迭代 Agent、何时启动或命名**节点 C**，并批准正式发布。单纯要求“继续训练”不代表提交授权。
- 专属训练 Agent 负责训练方法、候选模型、搜索算法研究、计算配置建议、性能与棋力验证，以及私有训练工件的留存；**不决定 ECLIPSE 正式版本号、产品型号或发布**。模型系统协调/迭代 Agent 掌管产品命名与应用集成。
- 已发布产品 ID 和权重不可因新的训练轮次而静默覆写；训练批次、checkpoint 编号、GitHub PR 编号不是已批准的产品版本。
- 未经明确授权，不写入 main、Inbox、模型目录、生产权重或 VeilLink，不上传私有棋谱/权重，不自行创建节点 C。Owner 明确委托的治理维护可在独立 feature 分支发 Draft PR，但不授予持续集成负责人身份。

## 二、双模型同代训练：Astra 与 Sol

每次获准训练周期都要计划并分别评估**Astra 高棋力候选**和**同代 Sol 低成本候选**：

1. Astra 继承合法且经验证的上一代训练能力，重点攻克深层攻防、强制战术、对手应手、可靠搜索排序和复杂局面。
2. Sol 优先从本代 Astra 蒸馏，并通过真实的拟合、模型压缩、算法优化实现成本下降。不得通过随机走错、忽略强制防守、减少合法性验证来人为削弱棋力。若只是同一权重配不同算力，只能标记为“Sol 搜索配置候选”，不得声称独立训练模型。
3. 在**相同规则、可比计算条件与交叉执黑白**的实测下，目标棋力顺序为：本代 Astra > 上代 Astra > 本代 Sol > 上代 Sol。它是**验收目标，不是训练后天然成立的结果**；胜率差异/置信区间不足则标为 NOT VERIFIED，不能制造结论。
4. 每个家族需要独立工件 SHA-256、实际加载身份、基座 lineage、验证记录和可回滚能力。不得将搜索时限扩大误称新一代模型。

## 三、自适应思考：预算上限不等于目标耗时

**总原则：由局面决定是否继续思考，时间只作硬安全上限，不按档位强制消耗到接近上限。**

- R15 当前 Swift 原生七档预算 130/260/520/950/1900/3800/5700 毫秒仍保持原样，**不是每步必须使用的时间**。此前讨论的 Sol 8 秒 / Astra 30 秒，仅是待独立测试、待 Owner 批准的研究候选上限；不得作为默认生产值直接写入软件或宣传为已部署。
- 在正常搜索前/中优先保障合法性、直接必胜、必要必防、可验证的强迫获胜以及危险双威胁。**可证明**的必胜/唯一安全应手可提前返回；不能将启发式评分高、棋步未变化、单次模型高概率等同数学证明。
- 自适应继续/早停要综合：战术复杂度、合法候选数、第一和第二候选的分差、多深度 PV 与得分稳定性、对手反击、节点增长速度、实际每层成本、下一层预计收益。缺失特征时必须报告未知，不得虚构置信度。
- **稳定收敛的提前停止**必须经过强制战术安全门，完成足够的深度和主要替代候选复核，并使用在独立验证局面上校准的阈值。不能只看“多层第一手相同”。仍有强迫反击疑问时继续搜索或标记不确定。
- 启动下一层前根据节点增长及剩余预算预测完成成本；难以完成时优先转向关键强制战术或停止，不要惯性开启注定被时间墙切断的整层搜索。若缩小宽度/放弃分支，必须在报告标明搜索覆盖变化。
- 始终维护最近一层**完整且合法**的最佳着法和主变化 PV；中断的搜索层绝不能覆盖完整层结果。强制防守安全回退必须可追溯，并把“硬超时、节点上限、主动取消、紧急回退、正常深度完成、已证明强制胜负、校准后早停”区分为不同终止原因；不得把超时伪报为证明或收敛。
- wall-time、节点数、内存、并发、iPhone 热状态、电量和 UI 可响应性均须有实测安全保护；硬上限必须生效。强制战术前置检查要有界且单独计时，不能因为保障棋力而无限冻结界面。异步搜索必须保留局面快照、取消和 generation token。
- Astra 偏重复杂局面的高收益计算，Sol 偏重每单位计算带来的棋力。两个家族都允许短局面快速返回、难局面使用更多资源。算力档是**选择上限**，不是强度/Elo 倍率，也不是自动生成的人民币费用。

## 四、训练数据、安全门与测量

- 保留真实用户重复战术的**有序着法、各次独立事件与来源**；来源快照重叠不能把同一事件重复计为新胜局，D4 旋转/镜像不计为独立对局。合成棋谱须明确标注 synthetic，不得冒充真人、Swift 正式 Bot 或高水平对手的实际对局。
- 单独统计真实对局、重复获胜战术、历史自对弈、合成测试；模型选择不能只看整体交叉熵。要报告完整合法落点交叉熵（nats）、Top-1/Top-5、样本数、校准方案、数据泄漏与历史验证复用情况。
- **必报的搜索效率指标：** 每步实际耗时 P50/P95/P99、节点数、完整搜索深度、峰值内存、真机热状态；并报告按终止原因分类的占比（主动收敛 / 战术证明 / 深度完成 / 硬超时 / 节点或内存限额 / 取消 / 回退）、预测下一层成本与实际成本、增加计算带来的有效棋力收益。
- **零允许的强制战术安全回归：** 合法性、一步必胜/必防、双杀/叉形、VCF、规则终局、搜索超时与回退必须独立测试。出现问题应回滚或拒绝候选；不得用较好的平均交叉熵掩盖。
- 对抗测试必须包括 Astra/Sol 与各自上一代及原版**实际已训练的 Swift ECLIPSE**，按照相同设备/规则/预算、同开局交换先后手开展足够多局对照并给出置信区间。原版空记忆环境的结果不能代替真实训练态棋力证明。
- 每次报告训练轮次完成度、模型导出复核完成度、实战棋力验证完成度和产品集成完成度等**不同百分比**；不得把训练完成 100% 误称软件已经接入 100%。

## 五、R15 交接契约与审批边界

- 训练 Agent 交付私有模型、实际 checkpoint SHA-256、模型身份/推理运行器、来源证明哈希、可重现配置、独立对局分组和评测。遵守 R15 现有的精确 handoff schema，不自行增减其强制字段。
- 自适应思考新增的终止原因、收敛证据、设备成本报告先作为**单独的本地私有 sidecar**提供，待获授权的迭代 Agent 另行扩展 schema/ABI；不能越权破坏现有 ABI，不能把私有棋路放进公开 PR/CI 日志。
- 运行器必须能通过独立身份查询证明实际载入的 checkpoint 哈希等于 manifest；仅有 JSON 声明不等于真实加载，单纯通过元数据门禁也不意味着获得产品晋级资格。
- Owner 说“提交/移交”之后才可通过指定安全渠道交付产物。**启动节点 C 还需要 Owner 另外明确指令。** 迭代 Agent 才负责模型目录更新、产品接线、真机/XCTest/实战回归及是否推进发布。
- 首次自适应搜索实现必须与现行固定上限搜索做同局面 A/B 对照，证明没有明显的强制战术、棋力、延迟和热稳定性退化。异常则保持旧生产路径，旧棋谱、签名和原发布型号不变。

## 六、治理生效与例外

本条款只约束被 Owner 指派到训练范围的 Agent 和评测验收接口，不自行赋权任何 Agent，也不改变 BOARD.json 的未分派状态。对规定有不同意见或需要例外时，提交明确的风险、依据、测试和回退方案由 Owner 审查。没有证据标 NOT RUN / BLOCKED / NOT VERIFIED，绝不自动补齐或假报通过。
