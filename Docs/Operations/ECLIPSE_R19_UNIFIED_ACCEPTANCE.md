## 分级发布决策

**A. 正式架构合并（可独立于模型实测成绩）**：在 R19 同一 head 所有相关 CI 全绿，检查所有文件来源后，Owner 可将源码合并 `main`，使 iOS Release 构建含 C++20 V2 搜索器与 Swift 控制器生产调用链。即使训练 Agent 模型未安装，应用也必须明确处于 `Swift fallback`，不能对外宣称最新 ECLIPSE 已在 C++ 下棋。

**B. 已完成训练模型的正式启用（不能仅靠 A）**：独立训练 Agent此前给出 `ECLIPSE-TRAIN-001.zip`（214 树、26 特征、C++ inference header、metrics 与 SHA manifest），需要原文件本体而非聊天摘要。安装真实 C++ scorer、验证模型权重文件 SHA 与 `ECLIPSE_ACTIVE_MODEL.json`、`eg_active_trained_checkpoint_sha256_v2` 回执来自实际加载的对象，完成真实棋局落点。该训练包目前不在本可访问分支及容器，所以没有假造提交或替代训练结果。

**C. 对外签名 IPA 及真机发布**：需要验证签名团队、profile、iOS 设备安装、手势及视效、蓝牙双机对局、后台行为、存档回滚与设备资源保护。仅 Linux CMake 成功不能宣称已发布。禁止自动将未核验的 Developer IPA 当成签名正式版。

## 验收纪律

- 先将所有需要的开发分支组合成一个可审核的 R19 候选源树，消除 10+ 个互相悬挂的 PR 作为发布入口。
- 正式 C++ 模型的 `compute_policy` 由专属训练 Agent 决定，`0/null` 为无硬编码上限；允许用户取消长时任务。
- 不允许训练数据重导出冲淡战术重复；同一战术多个历史快照保留原始来源并避免计作多局胜利。
- 不允许界面选 Astra 就把普通 C++ R10 原型说成 Astra 新训练权重。
- R19 校验脚本只证明架构布线。真的权重、棋力、签名、设备实测分别需要相应证据；拒绝以伪百分比替代实际通过的用例。
